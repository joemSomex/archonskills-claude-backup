# User-supplied `content-calendar.md`: curated source notes

This is a general content-calendar skill adapted for Quantum 13. Its examples and tools are not Somex commitments.

## Adopt

- Before asking questions, check existing conversation, supplied `.md` references, project context, known platform scope, release calendar, content pillars, and assets. Do not ask for weekly production capacity; the user will adapt the proposed content to workload. Group only essential unanswered questions.
- Offer a weekly or monthly calendar as requested. A calendar entry can include day/date, platform, pillar, specific topic/angle, format, proposed slot, source asset, and status. Make it possible to hand off to a scheduler without falsely claiming it has been scheduled.
- Offer a mix of content ideas and optional flexible slots without capping proposals to an assumed creation load. Mark any production needs so the user can trim or reschedule. Do not copy the supplied LinkedIn/Threads sample blocks into the Quantum 13 calendar.
- If the user requests batching, propose sessions by platform or source asset; otherwise keep the focus on content recommendations and schedule rules.
- Add a lightweight weekly review and monthly recalibration based on actual performance and available analytics; do not invent example performance figures.
- If a connected scheduler is explicitly requested, check available integrations, seek approval for the exact draft/platform/time, and verify scheduling by reading the queue back.

## Not automatically adopted

- The `.agents/social-media-context-sms.md` path is an optional file to check only if that project is supplied, not a prerequisite skill or proof a file exists. `content-strategy-sms`, `post-writer-sms`, `performance-analyzer-sms`, `platform-strategy-sms`, `content-repurposer-sms`, and BlackTwist are names in the source document, not confirmed tools or dependencies here.
- Do not turn 'no pillar >40%', 'no platform gaps >3 days', or '20–30% flexible slots' into universal rules. Confirm desired cadence and buffers with Somex; preserve breathing room where useful.
- Do not apply generic best-time tables for LinkedIn, Threads, X, or Bluesky to YouTube/Instagram/TikTok/Facebook/Reddit. Proposed times require local audience data or a clearly stated provisional assumption.
- The source's requirement for a Markdown table is not appropriate by default in Telegram. Use compact chat formatting; a table or document is optional if explicitly requested.
- Source advice to 'connect BlackTwist' is not applicable unless the user chooses it and the integration actually exists.
