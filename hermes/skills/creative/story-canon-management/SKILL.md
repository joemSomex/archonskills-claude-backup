# Story Canon Management

Preserve long-form narrative canon exactly while maintaining a compact, searchable continuity layer. Use this for chapters, prologues, scripts, world bibles, character dossiers, adaptations, and explicit “remember this” requests about a story world.

## Procedure

1. **Orient before writing.** Recall the project entity from durable memory, then locate and read the project’s existing canon index, README, source policy, chronology, and newest related source. Search the canonical archive, attachment-import area, and wiki for the title, installment, protagonist, supplied aliases, and remembered source paths before creating anything. For questions about why an author coined a character name, search provenance notes and conversation history as well as the canon archive; the finished spelling cannot establish which names were blended. Distinguish a recorded origin from a phonetic guess, and ask for a clue if the source pair remains unknown rather than turning a plausible blend into canon. Re-read the index immediately before patching when parallel ingestion may be active, because another worker can add the same installment between discovery and write. Do not write until the authoritative archive root is known; one project must not split across competing roots without explicit cross-links.

2. **Classify the submission and source relationship.** Decide whether it is a new installment, revision, adaptation, supplement, explicit replacement, or author-confirmed canon correction; record its medium, sequence relationship, release intent, and draft labels from both filename and internal title page. Default to parallel canonical adaptation records when a produced episode and written chapter/screenplay cover the same material: neither automatically supersedes the other. Cross-reference both, preserve source-local events and dialogue, and record differences without silently reconciling them. Exact produced dialogue comes from the author-supplied SRT; exact written dialogue comes from the canon-corrected chapter or screenplay. Only explicit author direction can replace a source or resolve one specific conflict. When the author declares all supplied chapters or screenplays canonical, treat draft labels as provenance—not as evidence of non-canon status—and retain each version until replacement or supersession is explicit. For a title, draft-label, character-attribute, or wording correction, keep the supplied source immutable, create a clearly named canon-corrected derivative, record the correction and provenance, and point current-canon indexes to the derivative. Ask only when the distinction changes the current canon decision.

3. **Preserve the source verbatim.** For an explicitly archived Telegram or Discord attachment, run the attachment-ingest workflow first so the original binary, provenance note, checksum, and extracted text are committed and indexed. Read the complete extraction before summarizing. Copy the verified original and a searchable extraction into the project’s existing versioned source path; include provenance, received date, sequence relationship, medium, and every conflicting draft label in frontmatter. Keep transport metadata outside the narrative body. Compute SHA-256 over the original binary and, for pasted prose, over the exact body—not the metadata envelope. Verify the binary checksum or exact-body comparison before acknowledging. Do not normalize punctuation, spelling, dialogue marks, names, or paragraph breaks.

3a. **Consolidate multi-turn visual worldbuilding on an explicit save request.** Read back the whole relevant decision sequence before writing: separate names and acronyms the author selected from assistant-proposed alternatives; preserve exact capitalization and expansion; distinguish a website display label from a faction's full name, and a fictional rank ladder from claims about real-world organizations. For each author-identified image, record the asserted identity separately from visible appearance and author-stated mechanics; do not infer implants, capabilities, cockpit visibility, or a released-episode appearance from the artwork. Archive earlier inbound references by copying them into the existing project source tree with original-path provenance and SHA-256 verification; the current-attachment ingest path is for current inbound attachments, not arbitrary files recalled from chat history. Dedupe byte-identical images by checksum while preserving every source-path alias in the manifest; count distinct selected references and reconcile that count against the author's full set before claiming coverage. Put the approved decisions in one additive, versioned faction/character note alongside preserved original sources, link the image manifest, then update the index, wiki, and compact durable-recall pointer. Before reporting completion, search current indexes, wiki pages, and active recall for provisional tiers, discarded names, and interim counts such as "remaining unselected"; replace stale synthesis with the final author-selected roster while retaining explicitly marked proposal history. Otherwise a partially saved batch can keep contradicting the consolidated decision. A request to save worldbuilding is not by itself a request to edit or deploy the website.

4. **Update the project index.** Add the source path, title, aliases, installment order, status, and precedence notes to the project’s canonical README or index. Summaries are retrieval aids, never substitutes for the verbatim source.

5. **Review adaptations from the complete source.** Watch or read the full adaptation before claiming a scene-by-scene reconciliation. Build a timestamped ledger with `episode-version`, `written-version`, `aligned`, `difference`, and `uncertain/not depicted` entries. A difference is not a precedence ruling: retain both versions unless the canon owner explicitly reconciles them. For local long-form video, follow `references/audiovisual-reconciliation.md`: verify the binary, inventory any author-supplied subtitles before transcription, use uniform full-runtime sampling rather than trusting scene-change coverage alone, transcribe locally in bounded chunks only when authoritative dialogue text is absent, and retain raw evidence separately from the cleaned canon record. Author-supplied SRT/dialogue files govern exact wording over Whisper; if they arrive after analysis, reconcile every cleaned dialogue anchor, resolved uncertainty, index entry, and durable-memory fact before declaring the corpus complete. If access is blocked, save only the author-declared precedence and verified metadata, state plainly that the adaptation has not been fully reviewed, and request an accessible source file; never promote descriptions, thumbnails, or remembered scenes into visual canon.

5a. **Align released dialogue when subtitles exist.** Preserve SRT cue indices, timestamps, and dialogue exactly except for corrections explicitly authorized by the canon owner. Cross-reference every cue against the governing screenplay for intended speakers and scene structure, then use the produced MP4 to resolve actual delivery, overlaps, off-screen lines, additions, omissions, and reassignment. Store one record per cue with speaker spans, confidence, and evidence; never guess silently. Produce a speaker-labelled SRT, structured cue map, revised-dialogue script, and discrepancy report by following `references/dialogue-alignment.md`. When no SRT exists, do not claim complete dialogue coverage from a screenplay or automated transcript alone.

6. **Extract canon anchors.** Record only source-supported chronology, character facts, relationships, locations, technologies, objects, turning points, production-format direction, and final state. For screenplays, capture the episode title, draft provenance, opening state inherited from the previous installment, causal handoffs, closing reveal, and any named release platform. Separate public knowledge, character knowledge, restricted in-universe knowledge, and author-only truth when the source distinguishes them. Compare against the neighboring installment and project index for name variants, appearance changes, numbering labels, legal terminology, and timeline counts. Preserve differences as parallel source evidence rather than silently choosing. For episode-versus-written comparisons, record both versions side by side with timestamps and passages; do not label either one governing, supplementary, replaced, or superseded unless the author explicitly issues that specific ruling. Explicit author corrections still govern the issue they directly address: when a produced line appears to conflict with a standing clarification, first test whether it is in-world shorthand and preserve the author's literal mechanics rather than erasing them. When the author resolves a conflict, propagate the governing value through the project index, installment page, character/entity page, chronology, and canon anchors in one pass; leave the original source and historical log untouched as provenance.

6a. **Develop new screenplays through staged story locks.** When helping the author build an unwritten installment, first lock the requested scope, protagonist objective, starting belief, ending change, antagonist's visible rationale and hidden objective, reveal ladder, power mechanics, and the causal reason for every lesson or set piece. Do not jump to scene structure while the author is still correcting the premise; revise the architecture first, then build a timed treatment, then screenplay pages. Keep suggestions labeled as proposals until the author approves them. Approved development decisions become **working story locks**, not released-episode canon; store them with that status, and expire or replace stale working-lock facts immediately when the author revises them. Follow `references/screenplay-development.md` for the detailed workflow.

6b. **Apply approved combat alternatives as bounded replacements.** Map each selected alternative to its original passage before editing. Preserve the encounter's causal outcomes, injury state, other characters' contributions, and sibling versions. Search the entire target screenplay for dependencies on removed mechanics, including severed weapons, retrieval, restraints, dressings, and later healing references; repair only those made inconsistent by the approved change. Distinguish a weapon's visual design from its inferred functions, and a character's separate powers from a shared visual motif: plant manipulation does not imply plant-mediated healing. When the author corrects a power mechanism, update the governing character source as well as affected screenplay passages without inventing additional limits. Verify both replacement anchors and absence of obsolete dependencies before reporting completion. When the author selects a unifying power mechanism, distinguish its separate applications from their delivery methods; rewrite action to demonstrate approved prerequisites and limits rather than merely renaming the ability. Establish required material and rescue structures before their payoff, and preserve a weapon's independent mechanical identity. Follow the power-to-choreography revision checklist in `references/screenplay-development.md`.

7. **Build the retrieval layer.** Create or update a small number of class-level wiki pages for the installment, central characters, and project timeline. Cross-link them to the immutable source and, when applicable, the canon-corrected derivative. Save one compact durable-memory fact under the project entity containing the installment title, sequence position, canonical source path, and decisive endpoint; raw prose does not belong in bounded memory. For a correction, recall every active fact matching the old title, label, or attribute, expire all superseded duplicates, write the replacement fact under the correct project or character entity, and verify the obsolete wording no longer appears in active recall.

8. **Verify every layer.** Confirm the immutable source exists, its body or binary hash matches, exact-body comparison passes, any corrected derivative contains the new value and omits the superseded value, the project index links to the governing version, chronology is correct, the adaptation ledger is backed by timestamps when applicable, and durable recall returns the new fact. Search current synthesis pages and indexes for stale values; exclude immutable raw sources and append-only logs from that stale-value check because they intentionally preserve history. For “do you remember all of them?” questions, build the answer from a filesystem inventory plus the canon index and durable recall—not memory recall alone—and enumerate the archived installments. Distinguish **all supplied and archived sources** from **all sources that may exist elsewhere**; never infer corpus completeness without an authoritative manifest or author confirmation. Do not claim an adaptation was watched or reconciled when only metadata was retrievable. Do not claim the material is remembered until both the verbatim archive and retrieval fact are verified.

9. **Report briefly.** State what was preserved, its sequence position, whether the source was fully reviewed, whether text was verified verbatim, and which retrieval/index layers were updated. For a multi-episode batch, send the requested per-episode heads-up only after that episode has passed the complete watch, written comparison, archive, index, and durable-recall gates—not when preprocessing merely finishes. For coverage questions, list the verified archived installments and state the scope limitation in one sentence. Do not replay the chapter unless asked.

## Audience-facing quizzes

1. Lock the audience's installment range and medium before drafting. For questions about released episodes, use produced-episode evidence and authoritative subtitles; exclude later development, author-only reveals, and written-only scenes even when they are canonical elsewhere.
2. Build a compact evidence ledger for each candidate question: installment, source passage or subtitle cue, correct answer, and two distractors. Retrieve bounded passages rather than dumping entire analyses into a single truncated tool result, because unseen middle sections cannot ground an answer.
3. For this user's daily terminal quizzes, provide exactly the requested number of questions, each with three options labelled A, B, C and exactly one correct answer. Vary correct-answer positions across the set. Keep questions concise and answerable from what viewers actually saw or heard; avoid distractors that are synonyms, partially correct, or dependent on unrevealed lore.
4. Put the answer key in a separate admin-only section with each question number, correct letter, answer text, and source episode. Do not mark correct choices inside the player-facing questions unless requested; this preserves direct reuse in a quiz interface.
5. Validate question count, three unique options per question, one evidence-supported answer, answer-key correspondence, and letter distribution before delivery. Deliver in chat unless a file or implementation is requested; do not turn quiz generation into a canon write.

## Always-On Rules

- Enforce the project's current canon-authority registry before every write using authenticated numeric identities, not display names. Resolve authority from the governing project policy rather than a copied single-owner roster, because delegated and shared ownership can change.
- Treat user-supplied canon as evolving unless the user explicitly declares it final.
- Preserve every supplied project alias exactly and make aliases searchable.
- Never silently replace an earlier draft, adaptation, or world-bible version.
- When the author declares every supplied chapter and screenplay canonical, preserve that as the default status until the author explicitly marks an item non-canon, superseded, or replaced; filenames and draft numbers alone do not change canon status.
- Treat produced episodes and corresponding chapters/screenplays as parallel canonical adaptation records by default; cross-reference both and never infer automatic medium precedence.
- During screenplay development, obey the author's current narrative scope exactly. If the installment is character-only or confined to one subjective plane, do not add external cutaways, parallel action, or other-character arcs unless the author reopens that scope.
- When the author reserves a character identity, survival, allegiance, hierarchy, betrayal, or causal role for a later installment, use the current scene only to build the approved emotional foundation. Do not add knowing reactions, visual clues, or dialogue that implies the reserved connection unless the author separately approves that foreshadowing.
- Keep three statuses distinct: **proposal** (assistant suggestion), **working story lock** (author-approved development decision), and **released canon** (archived screenplay/episode evidence). Never promote a proposal or working lock to released canon.
- Treat omission as absence of evidence, not contradiction, and never delete one source's detail because another medium omits it.
- Prefer author-supplied subtitles or dialogue files over machine transcription for exact wording; retain Whisper as searchable fallback evidence, not governing dialogue.
- Keep subtitle and MP4 timebases separate until matching dialogue anchors prove they are synchronized; cite both when they differ, and never use a subtitle from a longer assembly to claim absent visuals occurred in the supplied cut.
- In multi-installment reviews, maintain a programmatic manifest and verify the requested count before claiming the batch complete.
- Never convert inference, aesthetic interpretation, metadata, thumbnails, or a generated suggestion into canon.
- Preserve unresolved version-label discrepancies and ask only when a downstream task depends on choosing one. Once the author resolves a discrepancy, treat the correction as governing canon while preserving the original source unchanged for provenance.
- Do not infer that a prose `Chapter One` is also `Episode 01`; preserve source-local numbering until the author explicitly maps the labels. Once the author supplies an official title map, preserve its wording and capitalization, update the archive index, wiki, and durable-memory title pointers together, and retire any older “do not relabel” constraint so retrieval does not retain contradictory naming rules.
- Keep procedural memory in this skill, project facts in the project archive/wiki, and compact recall pointers in durable memory.
- When pausing multi-part screenplay development, consolidate approved work into one durable resumable treatment rather than relying on chat history. Label it as a working treatment, validate its part/scene count and required scene fields programmatically, link it from the project index, and store only a compact path/status pointer in durable memory.

## Pitfalls

- **Do not save only a summary** — summary-only retention destroys the author’s wording and prevents exact future revision.
- **Do not put full chapters into bounded memory** — large prose crowds out durable facts and still fails to preserve a reliable source artifact.
- **Do not create a second project archive before discovery** — duplicate roots produce conflicting chronology and source precedence.
- **Do not hash the frontmatter with the body** — changing provenance metadata would falsely appear to alter the authored text.
- **Do not index transport wrappers as prose** — gateway routing metadata and attachment notices are not part of the narrative.
- **Do not mark a source superseded from recency alone** — only explicit author direction establishes replacement.
- **Do not equate successful recall with complete corpus coverage** — durable memory stores compact pointers and can omit unindexed files; reconcile the archive inventory, canon index, and recall records before asserting completeness.
- **Do not trust the filename as the sole version label** — screenplay title pages can disagree, so retain both and expose the mismatch in provenance until the author resolves it.
- **Do not edit immutable sources to apply corrections** — create a canon-corrected derivative because provenance must retain what was actually supplied while current canon needs a clean governing text.
- **Do not retire only the first stale memory hit** — duplicate active facts can preserve the old title or attribute, so recall broadly and expire every superseded record before writing the replacement.
- **Do not infer installment equivalence from production notes** — labels such as `EP 01` inside a screenplay do not rename an author-established chapter.
- **Do not canonize character identity from sparse contact-sheet appearance alone** — cross-check the screenplay, subtitles, character bible, dense keyframes, and author corrections because stylized hair, costume, lighting, and framing can produce confident gender or identity misclassification.
- **Do not summarize from partial extraction** — screenplay continuity often resolves on the final page, so read through the explicit end marker before recording anchors.
