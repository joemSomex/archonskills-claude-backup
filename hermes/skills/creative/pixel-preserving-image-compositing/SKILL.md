# Pixel-preserving image compositing

Transfer or add text, logos, particles, lighting accents, and other graphic elements without regenerating the artwork or altering unrelated target pixels.

## When to Use

Use for bounded edits that must preserve source pixels, material-only variants of an immutable emblem, and verified transparent cutouts or overlay frames. For new avatar-frame concepts, route to the topical frame reference below rather than treating the request as a pixel-locked edit.

## Selective animation recoloring

Use verified material-only masks and one shared tonal mapping across frames; never regenerate a color-only edit. Preserve alpha and every outside-mask pixel exactly. Use the latest visual reference as color authority. Validate semantic boundaries before claiming preservation: outside-mask equality does not prove that a mask excluded skin, pupils, highlights, or eyelids. Never flatten an iris to its dominant color to suppress flicker; preserve its dark upper shading, amber midtones, gold highlights, pupils, and catchlights. For conversion-only requests, do not recolor or mask the artwork at all; prioritize existing colors during encoding and verify decoded pixels. See `references/animation-color-correction.md` for masking and verification.

## Timing-only GIF revisions

Use the GIF attached to the current request as the exact target rather than assuming the latest output folder is intended; visually similar four-frame and extended versions may coexist. Change delays without re-quantizing or altering artwork, and verify every decoded RGBA frame remains identical. Preserve the frame count, loop flag, transparency, and disposal behavior. See `references/animation-timing.md` for a lossless block-editing recipe.

## Procedure

1. **Classify the references by visible content.** Inspect every attachment and identify the element source, target canvas, and reference geometry (including object orientation, text baseline, hole/fastener position, line count, and reading direction) before typesetting. A style reference for an inscription also governs its orientation and alignment unless the user overrides them; do not keep a vertical inscription merely because the target product photo happens to hang vertically. For a horizontal dog-tag reference with the hole at left, rotate/crop the photographed blank tag to that reading orientation first, lay out text parallel to its long edge, inspect one calibrated preview beside the reference, and only then batch variants. Trust visible content over attachment order because messaging platforms can reorder files. When a follow-up includes an effect reference, the target badge, and a prior output, assign the prior output as a rejection/comparison baseline only; using it as design authority can carry forward geometry drift. When a follow-up mixes new texture samples with prior finished variants, compare decoded attachment pixels with prior exports before assigning design and material roles; a visually plausible reference may be an earlier output. If both the palette authority and immutable target are decoded-pixel-identical to a previously completed transfer, verify that export against the current target's alpha and dimensions, then reuse it rather than rerendering or claiming a new design; this avoids needless drift while preserving the exact prior result. Separate the samples from comparison examples, count only the samples as new treatments unless a new output count is explicit, and state that mapping on delivery; otherwise the reference count can be mistaken for the deliverable count. If the requested number of new outputs exceeds the independently supplied material references, make the extra output an explicitly labeled alternative from ONE reference rather than silently blending references or recycling an old export. When the first attachment is a master effect and all later attachments are distinct source designs, produce one output per later source with a shared material/lighting recipe, not multiple stylistic variants per source; the master supplies texture and atmosphere only, and each original supplies geometry.
2. **Choose deterministic raster editing when preservation is locked.** If the user says to keep the face, framing, crop, pose, lighting, or existing artwork unchanged and modify only one region, never deliver a full-frame image-to-image redraw as the final: it can change unrelated pixels despite preservation language. Use an alpha overlay or literal pixel transfer confined to a measured mask. When a requested fresh redesign is blocked and the user explicitly accepts recoloring prior outputs instead, process each original independently and label the result as a recolor, not a newly designed concept; geometry and file uniqueness do not turn a material edit into a redesign. For an exact-drawing color-grade request, first resolve the artwork image and the palette reference **by the user's explicit image numbers and visible content**, especially after an intervening description or earlier mistaken edit; do not let conversational recency substitute a different base. Transform the decoded original raster rather than redrawing it. Distinguish a *global* grade from a *background-only* grade before editing: a global grade may change all RGB values while preserving edges and geometry; a background-only grade must keep every protected subject pixel byte-identical after decoding, including hair, appendages, armor and glow. Sample actual shadow, midtone and highlight hex/RGB clusters from the palette reference's relevant regions (exclude accent colors when deriving its dark-blue background), then interpolate by source luminance so texture survives. Build a conservative subject-protection mask, check its overlay at full size, feather only **outside** that mask to prevent seams, and reapply original subject pixels after every blur/composite. Verify equal canvas dimensions and zero changed decoded pixels inside the protected mask, then visually inspect for missed fine limbs, ungraded background islands and halos; a successful pixel count proves protection only where the mask actually covers. Judge a global grade by spatial alignment and unchanged contours rather than zero pixel difference, and disclose any intentionally ungraded background near protected edges. For a clipped crown or other single-edge outpaint, first expand that edge on a new canvas with enough space for the missing anatomy and background, use generative output only as an aligned source for the new band, then composite the untouched original into the rest of the expanded canvas. Estimate alignment from overlapping features (e.g. ORB matching and RANSAC affine transform), blend a narrow junction, and check the crown seam at native scale; the generator often rescales its full-frame result even when told not to. When other new anatomy or exposed background must be synthesized, generate an aligned candidate only as local replacement pixels, then composite them over the untouched source. For paired mechanical hands added to existing blunt forearms, generate each hand-structure variant independently from the untouched source; compare unchanged armor landmarks with SIFT/ORB plus RANSAC before transfer. Draw a separate inward-feathered polygon around each old stub, new wrist bearing, palm and all fingertips, clamping the blurred alpha to the hard polygon so the torso, markings, legs and backdrop remain decoded-pixel-identical outside the two zones. Inspect enlarged left/right wrist crops for continuous load paths, intact digits, leftover stub tips and mask-edge cuts; different hashes do not prove distinct hand constructions. If a narrow original portrait does not match the image generator's fixed aspect ratio, pad it with measured white margins before generation rather than stretching or cropping the subject; retain the original at a known offset, downscale the candidate uniformly to the padded canvas, register unchanged armor/face landmarks with SIFT or ORB plus RANSAC affine fit, and composite only the permitted edit masks. Leave extra padding only where the new prop needs room, and verify every original pixel outside those masks at the known offset. For a mask-to-face or faceplate-to-skull replacement, crop the same original head with ears, neck and collar as alignment anchors, generate each candidate independently from that crop, and compare placement before transfer. Use an inward-feathered polygon around the whole changed head for a face replacement, or around only the front faceplate for a skull-mask edit; retain untouched ears, collar and any outer silhouette the user locked. For a hollow skull mask, check that both orbital voids, nasal opening and jaw grille read as recessed cutouts rather than painted lines; place any requested one-sided glow inside only its named socket. Reapply a hard polygon after blur so the feather cannot change protected pixels. At native-size crops, trace the full old mask footprint, including broken crown fragments and bright visor edges, and check both temples for white wedges where the candidate's hair diverges from the original; a clean pixel diff outside the polygon cannot detect these defects inside it. Do not merely shrink the polygon to hide a white wedge, because this can expose the old mask or a highlight as a white slash; instead reject that candidate or transfer a narrow aligned hair strip from another independently generated candidate within the same edit boundary, then recheck hairline, ears, jaw, neck and crown. For a requested gaunt undead face, inspect enlarged cheek hollows and skin tone on every final variant rather than assuming a prompt for sunken cheeks survives the full-body render. For a crown-texture-only revision, crop the untouched original around the scalp with the eyes and shoulders still visible as registration anchors; generate each pattern independently from that same crop, uniformly resize the candidate to the crop, align it by SIFT/ORB feature matches and RANSAC, then transfer only an inset scalp polygon with feathering toward its interior. Keep the skull silhouette, eyes, face and body outside that polygon byte-identical; compare decoded output to the original with zero changed pixels outside the polygon and inspect the scalp seam at native size. This prevents an apparently localized image edit from moving the face or changing the pose. For a small recessed tray or drawer, crop the source with enough rim and shelf context for generation, then register each independently generated crop back to that same original crop using unchanged surround features (for example SIFT/ORB matches with RANSAC homography); a model can rescale the tray even when the crop aspect ratio matches. Mask only the interior surface and any permitted inset behind its contents, feather inward, and reapply the original rim/front/neighboring bay above the candidate. Check the old object's entire footprint against that mask before compositing, or a clipped chain, blade, handle, or cast reflection can survive on a protected edge. For a lower-body-only transformation, crop the original from just above the waist junction through the bottom edge and generate independent replacement candidates from that crop; this focuses the model on the allowed geometry and avoids redrawing the face, hair, and upper body. Uniformly scale each candidate back to the crop width, align its top to the measured crop origin, then composite it independently onto the untouched full canvas. Do not stretch a square-ish output to the crop dimensions: scale uniformly and trim only excess edge pixels. When a reference lower body has a continuous curled appendage but edits from the original repeatedly create a detached return arc, make a **rough conditioning guide**, not a deliverable: place the immutable upper body over the reference's single-root-to-tip topology, remove duplicate hands and fragment ghosts from that guide, and ask the model to re-render the waist junction and whole appendage organically. Register the resulting candidate against unchanged upper-body features with SIFT/ORB and RANSAC before any pixel preservation. Compare a tight lower-body transfer mask against retaining the exact original upper band with a short transition: reject broad feathered unions that double armor seams or import rectangular studio-sweep patches. If seamless integration requires generated pixels in lower arms or other locked regions, disclose those changes explicitly instead of claiming everything else is unchanged; verify exactly which upper rows or masks remain byte-identical. Trace one waist root through every bend to one tip before accepting any variant. For a heel-to-flat-sole repair, inspect the side-facing boot first and define the acceptance geometry before generation: a thin, nearly constant-thickness outsole must run continuously from toe through arch to rear heel, with the rear contacting the floor; a filled arch, sloped wedge, grounded block heel, or contact shadow alone does not qualify. If the old heel shaft is built into the rear shoe upper, obtain permission to reconstruct that small rear-side panel rather than preserving a geometry that forces the heel to remain. Crop the boot with ample floor and unchanged ankle/toe landmarks; when image-to-image keeps reproducing the old heel, remove its full footprint to a white inpainting hole in the conditioning crop, generate independent photoreal heel/sole candidates from that same untouched source, and reject any that retain a separate heel. Register candidates to the original using unchanged armor features with SIFT/ORB plus RANSAC. Use a separate photoreal flat-boot reference for the *sole construction* when the original heel keeps being copied, but keep the current crop as the geometry and upper-boot authority; otherwise the model can shift the stance or redesign the upper. Generate each candidate independently, align left and right boots separately to their unchanged ankle/shin landmarks, and transfer the complete old-heel cleanup, new sole and contact shadow through separate inward-feathered masks over the untouched original. Hard-restore protected toe and ankle LEDs. Before batching, inspect each heel at native scale and at delivery size: trace one nearly constant-thickness tread continuously from toe through arch to rear contact, and reject wedges, detached heel posts, visible under-arch gaps, copied old fragments and mask seams. Compare decoded pixels outside each union mask, but do not mistake zero differences there for proof of ground contact. If a rear heel is fully occluded in a frontal source, say it cannot be directly visually verified from that view rather than claiming that every heel was checked. For additive particles or glow, read `references/localized-effects.md`. Distinguish a material-only recolor from an atmospheric light effect: the former preserves alpha exactly; the latter may add translucent alpha outside the opaque subject while protecting its structural mask and legibility. For a batch of transparent rank-frame recolors, first identify the exact current source attachments by visible design and compare their decoded pixels or hashes against prior exports; a follow-up may attach those exports as the new immutable bases. Choose one reusable primary/secondary/accent palette before editing, but if the user supplies exact HEX swatches or replaces a proposed rank palette, apply those swatches regardless of rank conventions and do not change the construction. Derive every output independently from its supplied frame. Preserve source alpha byte-for-byte and retain its value/metallic relief; recolor existing light or textured inlay panels toward the specified secondary or accent, map surrounding metal toward the primary and deep recesses toward the dark role. Limit each material mapping to the corresponding existing structure and feather only its color boundary: a hue-only global swap can turn intended silver rails gold, while a broad rectangular panel mask can overwrite trim. For a palette-frame-to-target-frame transfer, sample representative opaque primary/secondary/accent pixels from the palette frame, then map each target material's original luminance through its own shadow/midtone/highlight color ramp; combine a source hue/saturation discriminator with spatial masks for existing inner bevels and corner insets. Feather material boundaries narrowly, retain the untouched alpha byte-for-byte, and inspect the output beside the palette frame on dark and light mattes; a global ivory recolor can leave too little gold trim even when the metal relief survives. When the target is much brighter or darker than the palette frame, compare opaque-pixel value quantiles first; a monotonic, partially blended quantile map can bring target midtones and highlights toward the reference while retaining the target's own bolts, scratches, and reflection positions. Then map reference-derived hue and saturation by the remapped value, modulated by each target material's original saturation so ivory plates stay quieter than warm metal edges. Check that alpha and transparent RGBA are byte-identical, that source-to-output value ranks remain monotonic, and that the original relief and colorway read correctly on dark and light mattes. Do not impose a high Pearson luminance-correlation cutoff after a nonlinear tone map: valid contrast changes lower Pearson correlation without moving any seam or highlight. Return reusable role HEX samples from actual palette pixels, distinguishing them from variable specular highlights. Calibrate one frame before batching and inspect panel edges at native scale. Verify byte-identical alpha and dimensions, inspect every output on dark/light mattes, and measure leftover off-palette hue only above a brightness floor because near-black RGB quantization can report high HSV saturation; report the supplied base HEX colors exactly rather than treating specular highlights as new palette roles. When the user explicitly replaces the subject's material with a nonmaterial energy form, do not stop at a metal-tinted luminance ramp plus different halos: that leaves the shared subject visibly metallic. First inspect one transformed core at thumbnail size; if it still reads as metal, use a reference-driven light rendition as a texture candidate and composite it through the original structural masks. Preserving outer alpha alone does not prove the inner symbol or seams are exact, so inspect those separately and disclose any approximate reconstruction.
3. **Choose literal compositing when source styling is locked.** If the user requires the same font, texture, color, glow, cracks, particles, or effects, transfer the original pixels. For a helmet or other part taken from a near-identical but annotated reference, register the reference to the target using unchanged body landmarks (SIFT/ORB plus RANSAC), warp it to the target canvas, and transfer only the replacement silhouette plus the old part's footprint through an inward-feathered mask. Check that no annotation-color pixels enter the transfer mask, protect adjoining mounts and collar, and require zero decoded pixel changes outside that mask; a close visual match alone can hide a doubled old edge or red stroke. For a multi-view sheet whose helmets or horns must match, first inventory one design's horn count, hinge/root, sweep, tip, proportional length and material-color zones, then map that same topology to every rear, front and close-up view; camera scale or viewing angle is not permission for a new horn design. When turning a profile helmet close-up to face forward, design a complete bilateral shell, paired optics/eye apertures, ear modules and central bridge from the source topology before generating; copying or mirroring one glowing stripe onto a profile does not create a frontal helmet. If only the close-up may change, generate from a crop with hair/collar anchors, register the donor to the original, transfer the union of the old and new head envelopes, and verify that other sheet views remain pixel-identical; a bounded pixel diff alone cannot prove the face actually turned. Recover a verified unmarked base as in step 4, generate each structural variant independently from it, align each candidate by unchanged body landmarks, and transfer separate complete helmet envelopes onto that base with inward feathering. When a user reattaches an image after a previous localized correction, first compare its decoded pixels with the previous delivered file AND other recent drafts; use the exact attached version as the base even if it looks like the corrected one, because a different draft can silently undo the fix. When one view is the explicit helmet color/visor authority and another is wrong, compare enlarged crops side by side for crown-stripe width relative to each dome, black side panels, brow/cheek coverage, and visor branch junction and terminal; distinguish perspective foreshortening or lighting from a genuinely changed motif. **For color-only corrections, keep the attached target's head position, orientation, horn silhouette and visor path pixel-registered**: do not generate or paste a newly posed head. First decide whether the mismatch is material tone or panel *area/placement*: a palette remap cannot fix a mismatched black/white layout. For two nominally front-facing helmets, map each dome into viewer-left, center, and viewer-right material zones before editing; explicitly compare whether the authority has black on both sides of a centered white panel while the target reads as a black/white half split. Do not infer that narrowing the white stripe fixes a half split: that may leave its center offset and preserve the wrong visual hierarchy. Measure both panel boundaries relative to the dome silhouette and visor axis, then move the *material boundary* within the fixed helmet shell by locally replacing the excess white side with adjacent black material and restoring the missing white center, without translating the head, horns, or visor. Calibrate a side-by-side crop at equal helmet scale and inspect the edit at native size for displaced seams, stepped pigment edges, and old panel-border ghosts before committing to the sheet. If repeated corrections still miss the user's intended zones, ask which specific side should be black or white before another full edit; guessing from tonal summaries compounds the mismatch. For a tone-only mismatch, sample white, black and orange material pixels from the authority and target separately, excluding studio paper and neighboring armor; map the target's shadow/midtone/highlight quantiles within material classes through a tight helmet polygon with an inward spatial feather. Preserve all boundaries not explicitly corrected, preserve visor geometry, and hard-restore all pixels outside the mask. If the visor motif itself must change, edit its existing faceplate path locally and check that the head silhouette and pose remain fixed; a full-head generative correction can rotate the portrait even when the prompt forbids it. Use a generated donor only for an explicitly requested structural redesign, register it to unchanged body landmarks and transfer only the needed helmet envelope while protecting horns, hinges, collar and other views. Inspect an enlarged authority-versus-result comparison and the target seam at native size; verify equal canvas dimensions and zero decoded changes outside the permitted helmet area, because a convincing portrait alone can conceal shifted head position or altered neighboring armor. When a supplied reference already contains the exact requested wording, extract and move the complete lockup literally—never retype it or rebuild its material effect. If the original style reference is unavailable but a prior accepted composite survives, first compare that composite with the new clean artwork: reuse it only when dimensions match and a pixel diff proves all changes are confined to the old title zone. Transfer the accepted lockup from that verified composite, restore an obsolete numeral or subtitle footprint from the clean base, and construct any new glyph as a standalone asset. Never texture a new glyph by copying an old digit rectangle before removing its counters and negative-space holes; those voids reappear as fragments of the old numeral. Inspect the isolated new glyph and a native-scale final crop before acceptance, and label its rebuilt material as approximate when no original font or layered glyph exists. When a follow-up says to change only the wording while keeping the exact engraved font and material effect, return to the user's attached finished image as the immutable base, not an earlier approximation or blank product photo; enumerate every changed field (including ID digits), and leave every other panel, logo, line, and photographic pixel intact. Before editing, check whether the exact font/vector engraving source or all needed glyphs exist. If required glyphs are absent and no matching font/layered source is available, ask for that source rather than silently substituting a similar font or fabricating letters and calling the effect unchanged; offer a clearly labeled approximation only if the user accepts that tradeoff. For material-only badge work, calibrate one output against the user's currently assigned material reference at native and thumbnail size **before batching**; use a prior approved appearance only when the current request explicitly permits it. When the user requests restrained iridescent accents rather than a fully crystalline badge, soften source micro-scratches and candidate facet contrast, transfer low-frequency reference chroma onto exposed source relief, and protect dark recesses; inspect at thumbnail size to reject both saturated gemstone patches and flat chrome/silver. Do not carry this subdued treatment into a strongly iridescent request: a silver/blue badge with pastel edge lighting leaves broad exposed planes steel. Start from the immutable source raster with exact alpha and luminance topology. For a nonmetal crystal target, do not blend candidate color over the old steel ramp: replace exposed metal RGB with reference-driven crystal hue and fine surface texture, re-shade from softened source relief, and retain only the dark structural seams and cutouts; blending over steel leaves silver faces beneath pastel reflections. For multiple candidate finishes on one badge, vary broad embedded color distribution enough to distinguish them at thumbnail size, composite each from the untouched master, and wait for the user's selection before making one a collection standard. Follow `references/material-only-variants.md` for the transfer and verification recipe; material samples supply appearance, never object geometry.
4. **Measure all originals, validate the exact base, and establish the edit boundary.** Read actual pixel dimensions programmatically; visual-analysis dimensions may be approximate. When replacing one panel of a composite sheet, decide first whether the user wants a literal pixel transfer or a seamless redrawn sheet. For a literal transfer, register the donor to the target's divider, inventory every subject, blade, hair lock, glow, or shadow crossing it, and restore each crossing element from the untouched target through a tight overlap mask; a rectangular half-frame paste clips protrusions and leaves a visible join. Verify dimensions, protected-side pixels, and the complete crossing element separately. For a seamless redraw, route to reference-driven generation with the target and donor as separate authorities, specify the full replacement panel and every crossing element, and disclose that unchanged pixels are not guaranteed. If recolor is also requested across multiple views, mask each hair instance independently for literal edits; label hue-only variants as palette treatments rather than new character designs. For product engraving, measure the *actual editable plate crop*, not the whole photo: enlarging a tiny crop only interpolates its blur and cannot create legible metal grain. If the plate is too small to show realistic engraving at delivery size, request or use a new close-up source before batching; do not market upscaled placement studies as high-resolution product mockups. For paired footwear edits, inspect both shoes in a native-resolution lower-frame crop before defining masks: a front-facing shoe can conceal its heel while the other exposes a tall rear support. Mark each old heel, new sole path, retained upper/ankle details and permitted contact-shadow area separately; otherwise a symmetric broad mask can leave the visible heel intact or redraw protected boot armor. If image-to-image keeps recreating a high heel, do not keep prompting the full portrait or deliver a rough filled polygon: mask the complete raised-heel footprint in a lower-leg crop, use a separately grounded flat-boot construction reference, and generate aligned donor pixels for only the allowed heel/sole region. A black block that reaches the floor is still a block heel, not a uniform flat sole; inspect the negative space under the arch and tread thickness before compositing. If the brief says "masked area" but no actual mask is attached, inspect the target for an unmistakable empty placement area before asking: when the user delegates placement, choose a conservative floor/surface polygon yourself, record its coordinates, and keep the object's silhouette, shadow, reflection, and feathering entirely inside it. Do not treat a broad rectangular mask as permission to redraw existing fixtures or foreground clutter; protect those separately. Before accepting a generated placement, overlay its silhouette on the untouched source at native scale and trace nearby existing objects and their depth order. If a new case overlaps a protected fixture rather than empty floor, regenerate it in a clear area before compositing; a zero-difference test outside the polygon cannot detect an existing object erased *inside* it. Where overlap is physically intended, restore the source foreground with a separate occlusion mask and inspect the resulting contact boundary. Ask for a mask only when distinct plausible areas would produce materially different edits or the boundary cannot be chosen without touching protected content. When the user annotates a defect, search prior unmarked exports by resized-image similarity, **then compare every locked feature at native-scale crops** (especially exposed skin, shoulder cut, armor geometry and light slots) before accepting a match. If the markup is a distinct color, segment and slightly dilate that color, then compare decoded pixels outside its mask against a proposed unmarked base. When other parts of the uploaded image differ, validate the candidate only within the annotated subregion outside the stroke (allowing measured JPEG recompression noise), transfer its pixels solely through the dilated stroke, and retain the upload everywhere else; whole-frame similarity can silently replace unrelated newer edits. If no locally matching unmarked original exists, use the annotated image as the base and separate the markup's saturated-color stroke mask from the actual design-change polygons. When a thick annotation crosses structured armor or textured clothing, crop around all marked parts with unchanged landmarks, generate each clean candidate independently from that crop, and register its uniformly resized pixels to the original using SIFT/ORB plus RANSAC while excluding the annotations from feature matching. Transfer only the union of the dilated colored strokes and tight polygons covering the actual unwanted hardware; broad inpainting smears seams and full-frame generation changes protected areas. Feather inward at the outer boundary but force donor alpha to full opacity over every dilated annotation stroke, because partial blending leaves faint colored rings even when saturated pixels seem gone. Reapply the hard allowed mask, check zero changed decoded pixels outside it and absence of annotation color inside each marked component's bounding box (not the broad region, which may contain legitimate colored lights), then inspect repaired texture, zipper/rail continuity and mask seams at native size. For a marked multi-part hardware removal, count each circled component before editing and include its mount, attached cable, cast shadow, and terminal fragments in the allowed masks; inspect each component separately on the generated donor before compositing, because a model can remove one part while silently retaining another same-shaped handle or bracket. Re-inventory every new annotation against the exact unmarked base: an adjacent uncircled cuff or ring remains protected even if an earlier edit removed it. On a multi-panel illustration with a broad blank separator, first try tight per-object masks; if a regenerated honeycomb, grid, or other repeating texture leaves obvious phase-shifted seams or object ghosts at those masks, transfer the entire affected panel from an aligned clean donor across the empty separator and keep the unaffected panel pixel-identical. Verify that the separator has no visible junction and disclose that the affected panel was reconstructed rather than claiming a local pixel-only removal. When removing a marked buckle, reject a donor that substitutes a same-shaped dark square or grid clasp: the closure construction itself must disappear rather than merely changing color, because a color-matched latch still reads as the unwanted buckle.
5. **Crop generously, then isolate the element.** For a photorealistic correction, do not replace a photographed device with flat procedural polygons: unique hashes and pixel preservation outside the mask cannot make the insert look photographed. If the generator blocks the requested design, stop retrying that target with cosmetic prompt changes and disclose the blocker. Before substituting a literal style-reference transfer that the user did not authorize, search prior locally generated candidate assets for an independently designed, task-compatible insert. Reuse one only after proving decoded pixels outside the complete old/new prop footprint match the user's unmarked base exactly, inspecting the donor's geometry against the current request, and labeling the result as a reused design rather than a new generation; a unique file or a close thumbnail is not proof of a fresh concept. If no compatible asset exists, consider independently generating the allowed prop as a standalone photoreal product and compositing it onto the locked scene; use the isolated-product recipe in `references/localized-prop-edits.md`. Do not use this to relabel or retry a disallowed target, and report a shortfall if the isolated object is also disallowed or fails visual integration. Segment any donor with GrabCut or a verified light-background matte, remove source labels/decals, and composite it through a tight alpha silhouette over an unmarked base. For a shoulder-mounted isolated mechanism, erase the old projecting body without erasing the original lower bearing; place the donor hinge foot directly onto that bearing, match dark metal value, and add a small masked contact shadow before judging the seam. If a shallow donor leaves a visible white gap, shift the entire uniformly scaled asset toward the mount and re-inpaint any newly exposed old-hardware fragments; alpha extraction alone cannot make a floating machine part look integrated. Locate an exact unmarked base by comparing decoded pixels outside a dilated markup mask, not by visual similarity alone. Check the donor's entire hinge/contact, surrounding white wedges and foreground occlusion at native scale; disclose that material transfer is not an independently generated design. Include the complete glow and decorative effects. Remove only the source background with an alpha mask suited to the artwork. For an **existing exact-character cutout** with hair, glow, or particles, follow `references/transparent-cutouts.md` and mask the original rather than regenerating it. For a **newly posed or stylized avatar**, generate the requested rendition first, then use that same reference's chroma-key recipe to export real RGBA; disclose that the face and costume are generated likenesses rather than original pixels. When an opaque reference contains a detailed human silhouette against a textured background, do not approximate the cutout with hand-traced coarse polygons or paste a broad cloned rectangle: those methods carry background wedges, create halos and seams, and can leave the old figure visible as an extra person. Obtain a clean RGBA extraction or a verified segmentation first; if that is unavailable, produce one localized calibration edit and inspect it at full resolution before creating variants. For luminous red typography on black, use red-channel excess plus a brightness floor; see `references/typography-transfer.md`. For metallic outer-frame extraction, combine an edge-ring spatial mask, material-color discriminator, and connected-component cleanup; follow `references/metallic-frame-extraction.md`. For a generated open case with protruding caps against a similarly dark scene, isolate the lid, case body, and each cap with a verified silhouette mask before scaling the cutout uniformly into the clear floor area; a single broad perimeter carries triangular background wedges, while tightening that same perimeter can cut off brims or insignias. Recheck every protrusion and the floor-contact edge on the final composite after each mask revision, and regenerate at the intended scale if clean extraction is not possible.
6. **Composite only inside the allowed region.** For a white-to-black armor recolor on a white backdrop, inventory every light plate from helmet through knees before editing, isolate each plate with local polygons and material-color/luminance selection, and exclude the edge-connected near-white background before feathering. In OpenCV connected components, exclude label 0 from background IDs: it denotes all below-threshold pixels, including the subject, and would erase the intended selection. Reapply background protection after blur, then inspect plate tips, thin forearm slivers and knee edges at native size; a zero-difference check outside the edit polygons cannot reveal white fragments left *inside* them. For a white-head-to-black recolor in an image with multiple pale heads or skulls, name and crop the intended head first, trace its face-shell boundary at native resolution, and combine that spatial mask with high-luminance/low-chroma material selection; this excludes neighboring bone, colored hair and silver ear guards. Remap the selected shell's original luminance through a charcoal ramp so relief survives, leave dark eye recesses and perforation dots untouched, clamp feathering inside the mask, and inspect the forehead rim, both cheeks and pointed chin for leftover white pixels before verifying zero changes elsewhere. Preserve engravings with a luminance-to-charcoal ramp and place any eye glow in separately measured dark recess masks. For newly cut illuminated eye apertures in an otherwise unchanged mask, measure each eye position on the current source (not a prior variant), draw separate dark inset polygons with narrow metal bevels, clip dim interior light to each recess and the halo to a tight face region, then inspect both at native scale; this reads as a cut opening rather than a bright sticker. When only one eye should glow, keep the other socket dark. For the inverse edit, removing an eye beneath a mask, resolve viewer-relative versus anatomical side and mask the complete eyeball, eyelids, opening and enclosing rim; replacing only the pupil can leave the same eye-shaped feature.
