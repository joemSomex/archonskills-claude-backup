# Mecha and robot design from visual references

Use this recipe for character-sheet redesigns, armored-robot variants, and iterative armor corrections. The numbered source roles in the CURRENT brief override older reference assignments; do not pass an attached but unassigned image to the generator.

1. **Map roles before the first image.** Separate the base's style/material/lettering from later helmet, prop, construction, or function references. Record exclusions visible in role-limited sources (people, scenes, weapons, marks, exact armor). For a named full-body redesign, change head, shoulders, torso/back, hands, hips, legs, feet, and load connections rather than preserving the source silhouette by accident.
2. **Reserve each variant's topology.** Set a different silhouette and plate/limb connection graph before each independent call: low/wide versus tall/narrow, tracked versus legged, gantry versus monocoque, asymmetry, or different chest architecture. Different prompts or file hashes alone do not establish different designs. Keep front/side/back views consistent with the chosen structural count and side-specific parts.
3. **Lock count-sensitive geometry positively.** For four legs, assign front-left, front-right, rear-left, and rear-right attachment paths through each joint to four planted feet; reserve camera-side negative space for the far pair. Check actual paths rather than accepting a prompt's count. For held equipment, name each hand's grip and one continuous prop; if the user bans weapons or props, keep both hands visibly empty and build function into attached mechanisms.
4. **Obey a robot-only correction literally.** If the user wants nothing except the robot, remove functional demonstration vignettes, lifted loads, vehicles, rubble, tools, scenery, captions, inset parts and panel borders. Show function through integrated joints, grippers, stabilizers, and counterweights on the machine itself. When the user requests photorealism, specify studio PBR material response, realistic wear, lens/shadow behavior, and a seamless neutral backdrop instead of relying on a generic 'realistic' label. Calibrate one corrected image before repeating the batch.
5. **For an armor gender-presentation edit, work from the original base for every variant.** Identify the full unwanted armor contour (for example, paired rounded breast-like shells), replace that geometry with flat broad structural plating, and adjust adjacent ribcage/waist/hip proportions only enough to support the requested silhouette. Reserve distinct flat chest topologies for each variant; merely adding a center line or calling the same rounded shells masculine fails. Preserve the source helmet, signature shoulder, limbs, palette, framing, and empty hands unless changed explicitly. If every unrelated pixel must remain identical, use localized deterministic compositing instead of full-frame generation.
6. **Verify before delivery.** Count readable independent files, decode and check the actual ratio (image providers can return a square image despite a portrait/landscape request), and check hashes. For an explicit shared visual correction, inspect one calibration image and the corrected final batch; do not claim unchecked spelling, limb counts, empty hands, or consistent multi-view mechanisms have passed. If a provider refuses a prompt for safety, do not cosmetically retry it; only generate a materially different version after the user accepts the adaptation.
