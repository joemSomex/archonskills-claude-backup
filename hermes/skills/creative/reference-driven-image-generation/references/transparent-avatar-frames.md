# Reference-driven transparent avatar frames

Use for batches of circular profile-picture frames, especially when attached images supply different structural, material, effect and palette roles.

1. **Classify references before prompting.** Use a frame sample for construction and a texture or palette sample only for appearance; explicitly exclude their words, logos, watermarks, profile images and incidental object shapes. When the user praises an earlier slate, retain its finish and craft without recycling its exact panel layout.
2. **Reserve visibly different topologies before making a batch.** Mix thin continuous bands, staggered armor arcs, openwork rails, orbital wraps, inlaid circuits, radial fins and sculpted clasps where permitted. Give each prompt a different macro silhouette and fastening scheme; different hashes, colorways or micro-grooves alone do not establish different concepts. When the user favors striking variety over rigid uniformity, do not generate one identical annulus with progressively more ticks. When they ask for thinner frames, enlarge the clear aperture and reduce opaque frame area as well as merely narrowing a rendered edge.
3. **Generate one standalone frame per image.** Specify a centered circular *empty* photo opening, no element crossing that opening, full frame and padding on the canvas, and no text, characters, avatars or watermark. For reliable extraction when direct alpha output is uncertain, request one flat vivid chroma green both outside the frame and throughout the central opening and any true openwork. The green is an intermediate key, never a final background. Use the user-approved image provider for this workflow.
4. **Key and prepare at delivery resolution.** Segment green by `g - max(r,b)` on floating-point RGB (cast before subtraction so uint8 cannot wrap); feather the edge rather than applying a hard cut. For semitransparent pixels, replace green-spill RGB with a local average from nearby opaque frame pixels before resizing. Uniformly scale an oversized *whole* frame into the padded 1024-square canvas, never stretch axes independently, and suppress residual green-dominant edge pixels after downsampling. Keep real gaps transparent rather than flattening them into black.
5. **Verify every independent PNG.** Programmatically require 1024x1024 RGBA, zero-alpha canvas border and center, a substantial clear circular aperture (measure first visible frame pixel along radial rays), full frame inside the padded canvas, and enough connected foreground to rule out stray keying artifacts. Count files and compare hashes; use thumbnail/perceptual comparison when meaningful variety is part of the request. For a thinner follow-up, compare opaque-pixel coverage with the preceding slate rather than relying on the adjective in the prompt. Check palette histograms when the user asks for colorways or a restrained accent. A radial center test establishes a usable circular picture area, not that the generated inner contour is a mathematically perfect circle; do not overclaim.
6. **Deliver separate assets.** Attach each final PNG individually, not a contact sheet. State what was mechanically verified; do not claim visual QA if outputs were not inspected. If a particular frame fails the aperture, key, color or distinction gate, regenerate or repair that slot from its original references, not from another generated frame.
