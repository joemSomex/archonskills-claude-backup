# Fiction Canon Management

Maintain an evolving story bible, chapters, and screenplays without losing provenance or allowing stale facts to survive corrections.

## Always-On Rules

- Preserve every supplied source exactly as received. Never rewrite an original PDF, attachment, or verbatim extraction; corrections produce a separately labeled canon-corrected derivative.
- Read and enforce the project's canon-authority policy before any mutation. Verify the requester through the trusted platform identity already bound to the authority record; a display name, quoted message, forwarded text, or self-claim is not authorization. Treat every unauthorized change as a proposal requiring the canon authority's explicit approval.
- When a standing policy makes canon-corrected documents governing, use them as the primary source of truth wherever they differ from originals; retain originals only for provenance.
- Treat an explicit correction from the authorized canon owner as authoritative immediately. Update current canon views, indexes, summaries, and memory; preserve the superseded wording only as provenance.
- Track **captured in conversation**, **applied to the artifact**, and **committed to durable memory** as separate states. Never call a revision complete until each requested state has been independently verified.
- Preserve official titles, capitalization, sequence labels, character names, draft labels, and explicitly retained anchor dialogue exactly. If cleanup needs added causality around an anchor line, add it before or after the line rather than silently rewriting the line itself.
- Apply this precedence: latest explicit author correction → current canon-corrected derivative → current supplied chapter/screenplay → governing world bible → older sources and summaries.
- Separate three ledgers: **open plotlines**, **author-known but unrevealed truths**, and **continuity/canon questions**. Never present a planned future reveal as an accidental contradiction.
- Do not invent missing law, technology, motives, or connective scenes. Mark deliberately unwritten material as pending.
- Keep user-facing reports concise: what changed, what was verified, what remains unresolved.
- For copy-paste screenplay excerpts and prompt blocks, use ASCII-safe punctuation when the user's downstream editor corrupts smart typography: straight quotes and apostrophes, plain hyphens, and three periods. Preserve any explicitly locked typographic character only when exact source fidelity overrides copy-paste safety. When the author wants to work on a scene in notes, send the complete bounded scene as unfenced plain text with its screenplay spacing intact; keep commentary outside the scene so the text can be copied directly.

## Procedure

1. **Orient and authorize.** Read the project canon index/README, canon-authority policy, current sequence, correction records, and the relevant source immediately before and after the new installment. For a wiki, also read its schema, index, and recent log. Before changing canon, verify that the requester matches the stored authority through trusted platform identity; otherwise record the request only as a proposal and do not mutate governing canon.

2. **Capture and classify the source.** When the authorized author explicitly asks to remember or archive an attachment, archive it through the configured attachment-ingest workflow. Extract the full text, record the original filename, supplied title, draft label, sequence position, checksum, and provenance. Compare the document body, summary note, filename, and open-items section before applying it: if they disagree on a canon-changing fact such as count, hierarchy, status, title, or tier, ask one focused clarification and create a corrected derivative from the answer.

2a. **Build a revision ledger for multi-message development.** Read every authenticated author message in the source session in chronological order rather than relying on search snippets, the latest generated draft, or existing memory. Record each instruction's branch or option, exact retained lines, visual locks, placement, runtime, reveal status, and whether it is applied to the artifact and stored in memory. Later instructions within the same branch supersede earlier ones; instructions for a sibling option remain isolated unless the author explicitly merges them. Compare this ledger against the final artifact and active memory before declaring the work complete. If the latest continuous draft exists only as a chat response, archive it as a clearly non-governing development artifact before applying late corrections; compact memory facts are retrieval anchors, not a substitute for the full draft.

3. **Preserve an immutable source copy.** Store the original binary and a verbatim searchable extraction in a versioned source directory. Verify the copied binary checksum against the inbound attachment and confirm the extraction reaches the actual ending.

4. **Update the governing sequence.** Add the installment to the canonical timeline and project index using the author’s exact wording. Update the title-sequence fact rather than accumulating several incomplete title lists.

5. **Create retrieval anchors.** Record the episode progression, continuity anchors, character changes, objects introduced, cliffhanger, and any source-level discrepancies. Summaries are retrieval aids, never substitutes for the source.

6. **Apply corrections safely.** Follow `references/source-precedence-and-corrections.md`. Create one durable correction directive, generate corrected derivatives only where useful, and update all current canon surfaces. Retire or supersede stale database memories instead of adding contradictory active facts.

7. **Review development alternatives without promoting them.** Compare the option against the governing treatment, adjacent installments, and sibling options. Classify every finding as a true canon conflict, an internal logic conflict, a deliberate option variation, an author-known but unrevealed truth, or an unestablished addition. Keep option-specific hidden mechanics in a clearly labeled author-only section, preserve the option's non-governing status, and update the project index without implying that the option supersedes its siblings.

7a. **Reconcile complex intercut treatments causally.** For nonlinear internal/external stories, audit each thread separately and then audit every intercut boundary. Build a possession ledger for the contested object and a progress ledger for every simultaneous action. Establish geography, transport routes, detachable components, catches/brakes/clamps, connection state, prepared equipment, and the reason each route becomes unavailable before each payoff. Show how defenders are displaced before an antagonist reaches the protected object; preserve injury and resource costs across cuts; and insert observable external progress beats throughout long internal climaxes so a fall, firefight, charge, winch, or countdown never waits offscreen for several dramatic minutes. If internal subjective time expands while seconds pass outside, establish that differential at the first transition. When a system grants access through character choice, stage each permission independently and keep hidden exploitation out of experiential POV until the reveal.

7b. **Draft long screenplays from one shared production brief.** Before parallel drafting, write one brief containing the full beat order, exact dialogue anchors, character voices, power limits, forbidden material, geography, object-state ledger, intercut boundaries, and runtime budget; require every segment drafter to read that same brief and the same style references. Assign contiguous segments with deliberate overlap only at handoff beats. Assemble by stable scene markers rather than raw line numbers, then remove duplicated action, repeated reveals, and reset state at every seam. Run a deterministic final gate for exact anchors, forbidden scenes/terms, projected-versus-physical traits, monotonic damage or resource values, unresolved connection state, and a mechanically summed sequence budget. Read every join after assembly: independently good segments can still repeat a takedown, increase an integrity meter, reintroduce deleted material, or pause a simultaneous threat. For a screenplay too large for reliable chat delivery, attach the verified full artifact and report its word count, approximate page count, runtime budget, and remaining development status.

7c. **Learn dialogue craft from written/produced pairs before rewriting.** Read the governing screenplay, final produced transcript or SRT, alignment report, produced canon analysis, and targeted video evidence for several preceding installments. Build a character-voice matrix and separate recurring house style from episode-specific lines. Use produced compression, interruption, reassignment, and omission as performance evidence without treating the adaptation as an automatic correction of the screenplay. Rewrite around objective, resistance, turn, and subtext; remove dialogue that only narrates visible action or repeats established lore. Before polishing a line, test vague referents such as `it`, `there`, `they`, or `do it` against the preceding beat and the next reply; if the character's meaning is unclear, offer alternatives with distinct concrete intentions rather than synonymous phrasings, then let the author select. When action already proves a realization, test silence before generating dialogue. If dialogue is still needed, make each option a speakable, character-specific response to an immediate object or choice, not an explanatory thesis or ten mechanical paraphrases; read it into the next line to ensure the turn advances. For a sought-after saying, either verify an actual attribution or write an original saying-like line without presenting it as a proverb. After a breach of trust, write the immediate apology as a short speakable acknowledgment before any justification; a polished explanation in the first breath sounds rehearsed and can conceal whether the character actually answered the request. When the author deliberately removes an admission or warning, do not restore it while offering 'improvements'; preserve the exact semantic boundary so a courteous alternative does not change accountability or reveal timing. Preserve exact anchors and reveal state mechanically, then read the revised scene aloud and rerun canon checks because a more natural line can still leak knowledge or change a power rule.

7d. **Execute scene-note passes as performance rewrites, not line swaps.** Convert each note into four fields before editing: scene boundary, material to retain exactly, material to remove, and intended audience experience. Treat `keep as is` passages as byte-level locks: copy them unchanged into the replacement block and verify each exact string afterward. In urgent fights, chases, escapes, and medical crises, let the initiating line trigger immediate physical consequence; retain commands, tactical callouts, involuntary reactions, and short character-specific lines that turn the emotional or tactical choice. Do not strip a character-led symbolic fight down to uninterrupted choreography: use dialogue where denial or decision changes the action, but let a visible discovery play silently when the character tests and observes it. Exposition, quip chains, and lines naming a mechanism the audience just saw suspend danger. Check emotional continuity across the join: when a character learns they are being moved, isolated, injured, or unable to reach allies, give that fact an immediate behavioral and emotional consequence before pivoting back to lore or the next objective. In a first encounter with a complex world or guide, establish humanity through caretaking behavior, pauses, observation, and reciprocal curiosity rather than alternating question-and-answer exposition; let setting mechanics emerge through what the characters notice and do. After a guide is struck, stunned, or injured, give the protagonist a credible care response before renewed investigation unless characterization explicitly forbids it. Stage installed-memory or training sequences as dramatic experience already in motion: prove competence through choices, reveal identity bleed through sensory or behavioral discontinuity, and avoid static tutorial setup when the story requires momentum. Distinguish buying a person from buying their memories or records before writing the explanatory line; stage the stated transaction with evidence visible in the established POV, because swapping the object of purchase changes the story. If the memory record is explicitly pre-link, cut at the first established link rather than showing later shared perception as though it belonged to the original separate records. If a mirror antagonist or defensive construct is specified as silent, keep it silent and express adaptation through posture, copied technique, timing, and environmental response rather than thesis dialogue. For a reactive mirror, distinguish an ominous approach from an attack: the guardian may close distance, but let the protagonist initiate violence and demonstrate the response rule more than once before the nonviolent resolution; a guardian that strikes first has not earned that turn. Check whether the established barrier actually prevents retreat before making entrapment the reason to strike; if the protagonist can pass through it, let a filmable misreading of the mirrored weapon or a goal-driven choice prompt the first blow instead. Give a frightened protagonist a brief observable breath or pause before a defiant challenge so the emotional turn plays rather than appearing in dialogue alone. If contact makes the mirror flow into the protagonist, stage whether this is symbolic self-acceptance or a literal transfer, and keep its visual effects and immediate consequences distinct from any power reserved for a later reveal. When returning to a previously filmed or staged barrier, inspect the approach and recoil, map every intervening space, and resume at the established barrier; do not replay an approach location beyond it, because that silently moves the obstacle. When changing a weapon in a subjective space, establish who creates it and track its possession through each barrier, along with the character's occupied hands and tether; otherwise the staging implies an unearned ability or an impossible gesture. After the rewrite, search mechanically for every deleted phrase and required anchor, read the entry and exit joins, audit action geography and concurrent-thread progress, then recalculate page/runtime estimates from the revised artifact.

7e. **Apply line-level revisions to the actual screenplay artifact.** When an author supplies a full screenplay after earlier treatment work, preserve the supplied file as provenance and edit a clearly named derivative of that full screenplay; do not apply the note only to an older treatment with a similar option label. Read enough text before and after the target to preserve emotional causality and scene momentum. When the author selects one of several dialogue alternatives, apply only that choice; leave unselected alternatives unsaved. When an author pastes a working scene to mark where collaboration will resume, compare it with the saved artifact and the latest explicit decisions before treating it as a replacement; if it restores a rejected obstacle or staging rule, ask one focused question and carry the resolved geometry forward without silently saving the whole paste. Search the whole active screenplay for later replays, echoes, and callbacks of the changed line before calling the revision complete. Trace the whole callback chain: the original exchange, reenactment, borrowed quotation, and the listener's reaction must still make sense together. If the original scene is locked, treat it as the byte-for-byte source of truth and repair only the authorized later scenes; otherwise flag stale downstream occurrences for a separate decision. Distinguish an exact replay from a character quoting only the distinctive part of a longer line. When the author asks for a bounded screenplay excerpt, locate unique start and end anchors in the current saved artifact, confirm their order, and enumerate intervening headings before presenting text. For a character-only thread, omit external intercuts only when that scope is clear from the request or conversation, explicitly label the omission, and suppress repeated same-location return headings only in the chat display; never move those intercuts or headings in the saved screenplay. Preserve every in-scope action and dialogue line exactly rather than summarizing, and label any punctuation normalization as display-only rather than claiming a verbatim paste. When asked to cut directly between two scenes in a character-only thread, keep intervening external intercuts in their original full-screenplay positions; remove only the character-thread travel or bridge, then verify both the full scene order and the character-only extraction. Otherwise a local pacing request can silently rearrange the parallel action. For a continuous character-only fight interrupted by external scenes, keep re-entry cues in the full screenplay but use the same location slug each time; when presenting the character-only passage, suppress redundant re-entry headings if the author wants one continuous scene. A new room name in those headings falsely suggests the combatants moved. For a draft-film action-beat pass, compare only the filmed interval against the written derivative, sample broadly then inspect any subtle clue densely at its actual timestamp, and insert a missing visual beat where it was filmed instead of duplicating it in an unfilmed callback. Distinguish frame-visible traits from author-supplied design details, and confirm whether a character actually sees a clue before later dialogue relies on it. Keep draft-film provenance, source paths, and footage-cutoff claims in the companion alignment record rather than inside the performable screenplay; removing a boundary note must not turn written continuation into a claim of filmed footage. If a maintained character-only extraction or other generated companion exists, regenerate it from the current source after each accepted edit by mapping selected blocks to source scene ordinals rather than repeated heading text, and verify heading count and block equality; patching the extract independently or matching a repeated location slug can silently select the wrong passage. Refresh any previously delivered full-script and character-only text exports from that same verified source, comparing bytes or hashes, because an old attachment otherwise masquerades as the current draft.

7f. **Keep audits and selected fixes strictly scoped.** When the author bounds an audit to one passage, report only issues originating inside that passage; use later scenes only to test continuity, not to expand the review. Number findings stably and keep the user's chosen issue order. Before screenplay repairs, record the full working-draft SHA-256 and a SHA-256 of any locked prefix ending at a stable scene boundary. For one-issue-at-a-time work, present distinct options for only the next in-scope issue and wait for selection. Apply only approved bounded replacements. Verify the locked-prefix hash, then reverse every approved hunk in memory and compare the reconstructed full-file hash to the prior baseline; this catches unrelated edits across a multi-hunk pass. Anchor each reversal to its scene or occurrence rather than asserting the new wording appears only once: the same approved line may already occur in the locked scene. When reporting an audit, distinguish a definite contradiction, an unclear causal mechanism, an optional clarity improvement, and an intentionally withheld reveal; propose fixes in the unlocked downstream material first. Before calling a decision's urgency or motivation unestablished, trace the protagonist's earlier knowledge, external intercuts, and repeated environmental signals; subjective-time dilation does not erase an already shown threat, and an invented countdown can damage established causality. Re-read the resulting passage and neighboring beats because individually approved edits can create local repetition, but repair only the mechanical collision—not a rejected story, consent, or dialogue change. Advance to only one next issue, without editing its proposed solution before selection. An authenticated replacement is newer authority than an index summary or earlier approved wording; update stale summaries instead of treating the replacement itself as a conflict.

8. **Bound text transformations.** Restrict pronoun, name, and terminology replacements to the intended scene or exact word boundary. Never run a global pronoun replacement across a chapter; it can silently alter another character’s actions. Inspect the changed passage afterward.

9. **Reconcile counts and timelines.** When a cohort count changes, recalculate dependent totals with a tool and update every affected year or expansion count. Example pattern: changing an initial cohort while retaining a fixed final roster requires changing the later additions too.

10. **Maintain unresolved-thread tracking.** After each installment or review, classify threads as open, partially answered, resolved for the audience, unresolved only in-world, or author-known but unrevealed. Keep continuity errors separate from intentional mysteries.

11. **Verify current canon and acceptance criteria.** Run distinct gates rather than treating one audit as proof of another: (a) a deterministic checklist for exact dialogue, terminology locks, required scenes, status labels, and forbidden stale phrases; (b) when sibling options must share a spine, a beat-by-beat alignment map that removes permitted layers and compares every remaining action, disclosure, and consequence; and (c) a fresh narrative audit for causality, reveal timing, POV leakage, spatial continuity, power scope, and adjacent-episode handoffs. A canon PASS does not prove sibling alignment, and an alignment PASS does not prove the external causal chain. Fix every blocker and rerun a focused acceptance audit against the changed artifact; a pre-fix audit is not completion evidence. Search current summaries, corrected derivatives, indexes, active memories, frontmatter, and author notes for obsolete names, spellings, numbers, titles, rules, pending-status language, false `matches`/`finalized` claims, and superseded descriptions. Apply terminology locks case-insensitively across governing derivatives and synthesis pages while excluding immutable originals and append-only logs. Searches may still find obsolete text inside immutable originals; label that as provenance rather than active canon. If an exact runtime target is retained, attach a sequence budget and calculate its total mechanically. When consolidating multi-author or author-plus-reconciler work into one editable version, preserve the original source ledger, add the authenticated reconciliation provenance separately, and remove `active reconciliation` labels only after the post-fix gates pass.

12. **Report completion.** State the canonical changes, corrected derivatives created, original sources preserved, checks performed, stale memories retired, and remaining deliberate open items.

## Plotline Review Format

Use this order when asked for unresolved plots:

1. Immediate cliffhangers
2. Central season mysteries
3. Character and relationship arcs
4. Secondary dangling threads
5. Continuity/canon decisions
6. Already resolved items that should no longer be tracked
7. Highest-priority questions for the next installment

For each item, give the setup, latest development, and exact unresolved question. Distinguish strong inference from confirmed canon.

## Pitfalls

- Do not silently edit an immutable source to make canon appear cleaner; doing so destroys the evidence needed to understand later revisions.
- Do not keep both the old and corrected fact active in memory; retrieval may surface the stale one unpredictably.
- Do not treat a screen character’s explanation as objective canon unless the author confirms it; dialogue may encode institutional belief, propaganda, or incomplete knowledge.
- Do not normalize an author’s naming or capitalization for style. Exact names are continuity data; when the authority discontinues a spelling, remove it from every governing derivative and current synthesis surface, but keep it in immutable provenance sources.
- Do not resolve contradictory counts or hierarchy from context alone. Ask the authority because a document can list four entities while separately declaring only three as top-tier.
- Do not accept canon mutations from collaborators merely because they can access the shared bot or use the authority's display name; shared messaging access is not canon authority.
- Do not call an intentional future reveal a continuity error. Track it as a deliberate open plotline with a reveal status.
- In a declared single-POV treatment, keep hidden motives and author-only mechanics out of experiential narrative prose; place them in labeled development notes, because omniscient explanation weakens both POV discipline and reveal control.
- When a reveal depends on a character concealing a visually obvious trait, establish how the mental space, disguise, lighting, or viewpoint hides that trait before using the revelation; otherwise the later deduction has no valid premise.
- Separate systems that share imagery by giving each a distinct trigger, scope, and visual behavior; otherwise audiences will infer a false common origin even when the outline labels them separately.
- Do not replace an explicit scene-space attribute with a broader physical canon default; a projected avatar, memory image, disguise, or simulation can intentionally differ from the character's physical body.
- Do not treat a regenerated or cleaned draft as proof that every prior revision survived; long outputs and search snippets can omit later opening, climax, runtime, or exact-dialogue instructions without making the omission visible.
- Do not let a long emotional or internal scene pause a simultaneous extraction, pursuit, countdown, or battle; intercut observable progress beats because otherwise the external threat appears to wait for the dialogue.
- Do not let an outline summarize possession changes such as “they regain it” or “the enemy retakes it”; show the concrete displacement, route, and handoff because compressed action summaries often violate the geography established one paragraph earlier.
- Attribute each machine reaction to a causal system already in scope. If a power suppresses characters' abilities but not ordinary electronics, use a separately established overload or mechanical fault for flickers, locks, and failures; otherwise the scene silently expands the power's rules.
- Do not declare sibling options aligned because their broad beats match. Compare the shared spine sentence by sentence after stripping permitted intercuts; small unmatched reminders, early exposition, or changed authentication staging can alter reveal timing and mechanics.
