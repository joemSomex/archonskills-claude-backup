# Quantum XIII achievement badge concepts

## When to Use

Use for the user's recurring five-concept badge-design prompt and for named rows of the Badges.xlsx achievement list.

Generate a **design-selection slate**, not five achievement-level colorways. The chosen concept later becomes the master for its five ranks.

## Achievement-specific design requirement

"The badge design must directly represent the specific achievement described in the provided achievement details. Choose symbols, shapes, and visual elements that clearly communicate what the achievement rewards. Avoid generic sci-fi designs or decorative elements unrelated to the achievement. The badge should be immediately recognizable as a visual representation of its achievement while maintaining the Quantum 13 aesthetic."

1. Read the actual workbook at runtime. Treat the first data row after the header as achievement entry 1 when the user says "row 1" in the context of completed generations; also inspect literal Excel row numbers and resolve ambiguity from the user's completed-entry context. Capture the exact `Type` and `How to get` wording, plus all five level labels as context. Distinguish actions that sound similar but are separate rows: posting comments vs gaining upvotes, answering daily quizzes **correctly** vs attempting daily/weekly quizzes regardless of result. Do not put any level numbers or labels inside concept art.
2. Inspect every attached reference by visible content **for each new entry or remake**. The user may provide fresh reference images with future generations: treat that entry's newly attached images as the active design-learning sources, map what each contributes (material, painterly surface, bevel, silhouette clarity, relief, construction), and do not silently reuse a fixed old reference list in place of them. Preserve any compatible explicit constraints and use older liked examples only where still relevant. For stock fantasy badge sheets, extract sculptural/painterly relief, bold central-symbol integration and legibility, but exclude watermarks, collage/sheet layout, fantasy weapons, skulls, shields, heraldry, typography and their exact symbols. Turn those style lessons into an original circular Quantum XIII science-fiction badge for the earning action; never reproduce a source icon or its watermark. If fresh references suggest a new style, translate their visual characteristics into the current five prompts instead of repeating the prior metallic-disc template.
3. Reserve five genuinely different **circular** constructions and five different central-symbol integrations before generation. Vary structural topology (solid recessed coin, openwork frame, iris, layered medallion, split or interlocking ring) and the meaningful visual metaphor, not just bevels or camera angle. When a prior slate is rejected, inspect it as a rejection baseline and prohibit its repeated shapes in every replacement prompt: for forum thread-posting, avoid another grid of blank rectangular chat tiles or identical segmented rims; explore originating paths, branching structures and woven thread forms instead. For upvotes on forum posts and comments, do not equate five prompt variants with five designs if they all resolve to an oversized upward arrow on a speech rectangle; inspect the contact sheet, replace repeated slots with alternative endorsement structures, and reject accidental Wi-Fi waves, smiley faces, pseudo-text UI cards or baked checkerboard even when they pass basic image encoding checks. Keep the action unmistakable at 48px: before accepting, identify separately where the awarded object and the rewarded action appear in the actual image. If either is merely implied by an abstract plate or decoration, reject it. For posts-only upvotes, a recognizable post/publication panel (flat-cornered, no speech tail) AND a prominent upward-vote arrow must be visibly integrated at thumbnail size. When a user supplies a comment-bubble-with-up-arrow reference for a posts-only remake, transfer its obvious vote signal and graphite/pewter relief but replace the speech-bubble outline with a distinct post panel; do not copy the entire comment symbol or confuse it with the combined posts-and-comments achievement. A user-supplied reference can override an older blanket aversion to arrows when semantic clarity requires one. Make the five variations differ in how the two symbols join and in ring construction, not merely surface filigree. Avoid unrelated generic sci-fi decoration, emoji, oversized checks, lettering, numerals, figures, excessive neon and ornamental noise. For quiz correctness, communicate a solved/precisely matched answer rather than mere participation; do not reuse comment-bubble or upvote imagery. For achievements conditioned on a named member rank, use the actual website rank badge if provided and requested; if the user explicitly forbids using the rank icon, omit its shape and color entirely, including abstract or recolored variants, and convey helping newcomers through the requested social-action motif instead. If the user requests exact rank-art insertion, place literal source pixels on the thread-owner/source side and verify transparency; if the user requests the rank badge as a design reference but explicitly forbids its colors, preserve its recognizable geometry in the same neutral graphite/pewter material as the achievement, never paste the source gold. Respect the current request's reference roles over an older localized-composite approach. For community-help achievements, if the user asks for a handshake theme, show an anatomically legible clasp at thumbnail size while still depicting a distinguishable comment/reply bubble. If the Cadet icon is forbidden, do not add an inverted V or rank marker to the original thread; a handshake by itself communicates welcome, not commenting. Reject renders with only one shared bubble or a baked checkerboard, even if the handshake looks polished.
4. Generate five independent images with the user's exact shared constraints: neutral graphite/pewter or comparable consistent metal, same visual scale and detail density, circular outer form, no in-badge text, transparent background and 1000x1000 PNG. For this user's image generation use ChatGPT/OpenAI only; do not use Claude or Higgsfield. Use original inspiration images on each call, not a generated sibling, and require one badge per file rather than a collage. If transparent output is not reliably available, ask for one uniform vivid chroma-key background including all internal holes; key the background deterministically and inspect the resulting alpha on dark and light mattes.
5. Verify all five **actual files**: PNG, 1000x1000, RGBA with alpha zero beyond the badge, no baked checkerboard or chroma fringe, non-identical hashes, circular silhouette, matched nonzero-alpha bounding-box occupancy, clean small-profile readability and meaningful visual variety. Replace only failing concepts. Keep previews/contact sheets internal; deliver the five accepted standalone files as bare `MEDIA:` lines in Discord.
6. When the user says "send row 3 first" or otherwise sets a review gate, deliver only that row's five concepts and STOP. Do not start subsequent workbook rows until the user reviews or explicitly directs continuation. Do not archive temporary attachments or make canon changes as part of badge work.

## Output

Briefly name the interpreted workbook entry and the verified count/format. Supply the five separate files. Avoid claiming approval or definitive-master status until the user selects a design.
