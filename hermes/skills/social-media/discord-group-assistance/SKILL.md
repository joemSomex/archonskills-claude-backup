# Discord Group Assistance

## Workflow

1. **Identify the speaker and target.** Distinguish the current author, mentioned users or roles, the bot account, and any quoted or referenced member. Do not assume every mention targets the same account.
2. **Inspect channel context when a missed reply is reported.** Use the Discord message-reading action to fetch a bounded recent window from the current channel. Find the referenced member's latest messages, verify whether they mentioned the bot, and determine whether the request remains unanswered.
3. **Complete the missed request immediately.** Respond to the substance of the pending request rather than only explaining the routing problem. Mention the waiting member when useful so the answer is visible to them.
4. **Preserve the requester’s language.** Answer or supply the requested artifact in the language used by the waiting member, while keeping explanations to the current user in their preferred language.
5. **Handle long outputs as attachments.** If a translation, prompt, or document is too long for a clean Discord message, write it to a plainly named UTF-8 file and attach it with a one-line description.
6. **Report only verified routing facts.** Say that a message was visible in channel history or absent from the active conversation stream only when the fetched history supports that distinction.
7. **Verify live server state before quoting limits or perks.** Separate Discord-wide account limits from guild boost-derived limits and channel-specific settings. Prefer the Discord administration connector's server-info action; if it does not expose guild metadata, resolve the active secrets file with `hermes config env-path`, read only the exact bot-token key without printing it, and call `GET https://discord.com/api/v10/guilds/{guild_id}` with bot authorization. Use `premium_tier`, `premium_subscription_count`, and `features` as the evidence for the server's current state. Check current official Discord documentation in the same turn because boost thresholds, account upload limits, and experimental perks change.
8. **Explain boost arithmetic and upload scope precisely.** Compute boosts remaining from the live subscription count and the current official threshold rather than from a member's claimed contribution; other members may account for the difference. Server Boosts apply to the entire guild, not one channel. Distinguish the guild's level-derived upload limit, each member's Nitro entitlement, and optional tierless perks such as separately purchased larger uploads. Do not infer that an experimental perk is active merely because its feature flag is present; verify activation or label it as available.
9. **Resolve member identity before checking authorization.** A typed display name such as `@Name` is not a reliable Discord identifier and may not be a real mention token. Prefer the connector's member search. If member search is unavailable but a candidate user ID is known from nearby context, resolve it with `GET /guilds/{guild_id}/members/{user_id}` using the bot token loaded from the exact active-profile secret key without printing it; compare the returned username/global name/nickname to the requested person. Only then compare the canonical user ID with `DISCORD_ALLOWED_USERS` or authorized roles. Never infer authorization from a display-name match alone, because names are mutable and non-unique.
10. **Trace authorization before blaming mention handling.** When channel history contains a message but the gateway never routed it, inspect the active profile's `gateway.allow_all_users`, `DISCORD_ALLOWED_USERS`, `DISCORD_REQUIRE_MENTION`, and `discord.free_response_channels`. Treat Discord user IDs and channel IDs as different types: user IDs belong in the allowlist; channel IDs belong in free-response configuration.
11. **Repair the active profile without losing access.** Resolve its `.env` with `hermes config env-path`, merge new user IDs into `DISCORD_ALLOWED_USERS` while preserving existing entries, and use `hermes config set discord.free_response_channels <channel-ids>` rather than hand-editing `config.yaml`. When inspecting `.env`, emit only the exact non-secret keys needed; never list every `DISCORD_*` line because that prefix also matches `DISCORD_BOT_TOKEN`.
12. **Choose the mention-free scope explicitly.** For one or several dedicated chat channels, append their channel IDs to `discord.free_response_channels`, preserving existing valid channels and removing any mistakenly stored user IDs. When the user clearly wants every accessible server channel to respond without tagging the bot, set `DISCORD_REQUIRE_MENTION=false` in the active profile's `.env`. Keep the user or role allowlist in place; mention-free routing must not silently become public access.
13. **Check Discord prerequisites.** Verify the bot or its role can view the target channel, send messages, read history, and attach files. Mention-free replies also require Discord's Message Content Intent; if the bot connects but cannot read ordinary messages, verify that intent in the Developer Portal before changing routing again.
14. **Use channel overrides for “only this chat” model changes.** Treat “this chat” as the current Discord channel unless the user explicitly asks for only their personal conversation route. Set both fields with `hermes config set platforms.discord.channel_overrides.<channel_id>.model <model>` and `hermes config set platforms.discord.channel_overrides.<channel_id>.provider <provider>`, then verify the exact override and the unchanged global model with `hermes config get platforms.discord.channel_overrides.<channel_id>` and `hermes config get model`. Use the provider-native model slug—for OpenAI Codex’s expanded GPT-5.6 context, use `gpt-5.6-sol-900k` with provider `openai-codex`. Channel config is read on the next turn; do not restart the gateway solely for this YAML override. Remember that a sender’s existing session `/model` override has higher priority than the channel default.
15. **Activate and verify authorization or mention-policy repairs.** After `.env` routing changes, restart with `hermes gateway restart`, confirm `hermes gateway status`, verify only the required non-secret user, channel, and mention-policy keys, and check recent logs for both the Discord gateway connection and the bot identity. These repairs are not complete until the running gateway has reloaded them.

## Always-on rules

- In group channels, treat requests from any member who directly mentions the bot as actionable; this user expects the bot not to respond exclusively to them.
- When someone says another member is being ignored, inspect recent channel history before answering—the active conversational stream may omit messages that are nevertheless present in the channel.
- Do not blame the member or claim they failed to mention the bot until the exact message has been checked.
- Do not stop at an apology when the missed task is recoverable; perform it in the same turn.
- Never place a member ID in `discord.free_response_channels`; the gateway interprets that field as channel IDs, so it does not authorize the member.
- Add newly authorized members to the existing allowlist rather than replacing it, because replacement can silently lock out previously approved users.
- Keep mention policy separate from authorization: `DISCORD_REQUIRE_MENTION=false` changes when authorized users trigger the bot, not who is authorized.
- When explaining how to activate a new channel, present two explicit paths: mention-only needs Discord channel permissions and an authorized sender; mention-free additionally needs the channel ID in `discord.free_response_channels` and a gateway restart. This prevents unnecessary routing changes when ordinary mentions are sufficient.
- Query exact `.env` keys rather than broad platform prefixes, because secret tokens commonly share those prefixes.
- Never infer a guild's boost tier from visible chat behavior; read live guild metadata, because account entitlements and server perks can produce similar upload behavior.
- Never describe a Server Boost as channel-specific; boosts apply guild-wide even when the question originates in one channel.
